# 本番環境におけるデータ運用戦略（ハイブリッド構成案）

本ドキュメントは、先生と生徒が離れた場所にいる本番環境を想定した、3Dデータおよび学習データの効率的な運用方法についてまとめたものです。

## 1. 基本コンセプト：ハイブリッド・データストレージ

「真実のデータ」を保存する**クラウド（外部DB）**と、表示の高速化を担う**端末内保存（IndexedDB）**を併用する構成を推奨します。

### 構成の役割分担
- **外部データベース (Cloud Storage / DB)**
    - **役割**: マスターデータの保管、異なるデバイス間での同期。
    - **保存内容**: 3Dモデル原本（.glb）、児童の進捗、ガチャの権利フラグ、アカウント情報。
- **ローカルキャッシュ (IndexedDB)**
    - **役割**: 重たい3Dデータの再ダウンロード防止、アプリケーションの高速レスポンス。
    - **保存内容**: 一度取得した3Dモデル、高解像度スクリーンショットのコピー。

---

## 2. 具体的な運用フロー

先生がデータを登録し、生徒がガチャを引くまでの具体的なステップです。

1.  **先生による登録（アップロード）**
    - 先生が管理画面から児童のマイクラ作品をアップロードします。
    - データはクラウド上のストレージに保存され、DBには「児童Aがガチャを実行可能」というステータスが書き込まれます。

2.  **生徒による同期（チェックイン）**
    - 生徒がタブレットを起動すると、まず外部DBへ「自分宛ての新しい更新があるか」を問い合わせます。

3.  **初回のダウンロードと二重保存**
    - ガチャ演出後、3Dデータを表示する際、クラウドからファイルをダウンロードします。
    - **重要**: ダウンロード完了と同時に、そのバイナリデータを**IndexedDBにも保存**します。

4.  **2回目以降の高速表示**
    - 次回以降、同じ作品を表示する際は、インターネットを使わずタブレット内のIndexedDBから直接読み込みます。

---

## 3. この構成を採用するメリット

| メリット項目 | 内容 |
| :--- | :--- |
| **ユーザー体験 (UX)** | 3Dモデルが瞬時に表示され、子供たちの集中力を削ぎません。 |
| **通信環境への配慮** | 学校等の限られたWi-Fi帯域を圧迫せず、安定した動作が可能です。 |
| **運用コストの削減** | クラウドからのデータ転送量（Egress）を最小限に抑え、維持費を安くします。 |
| **オフライン対応** | 一度見たデータであれば、一時的にネットが切れても表示し続けることが可能です。 |

---

## 4. 将来的な実装に向けた技術選定（参考）

- **バックエンド**: 
    - **Firebase**: リアルタイム同期が容易。Firestore + Cloud Storage の組み合わせ。
    - **Supabase**: SQLに基づいた厳密なデータ管理とスケーラビリティ。
- **フロントエンド同期ロジック**:
    - `idb-keyval` 等を用いたシンプルなIndexedDB操作。
    - データのバージョン管理（クラウド側のファイルが更新されたらキャッシュを消す仕組み）。
